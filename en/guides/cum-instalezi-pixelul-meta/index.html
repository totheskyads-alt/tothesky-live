How to install the Meta pixel correctly in 2026, plus Conversions API

To The Sky · 25 November 2026

Install the Meta pixel through Events Manager, configure the relevant events, and check that the data matches the actions taken on your website. For a complete setup, add Conversions API, deduplicate events, and check marketing consent before activating the pixel.

Events to check for your store or service website

Why does the Meta pixel matter for your business?

The Meta pixel, still often called the Facebook pixel, sends Meta events about actions taken on your website. For an online store, these can include viewing a product, adding it to the cart, or making a purchase. For a service website, we also care about enquiries submitted by potential customers.

A Facebook pixel installation should be assessed by the data it sends. Adding the code to your website is only the beginning. If the same purchase appears twice or arrives with the wrong value, you are interpreting results from incorrect information.

At To The Sky, we are a young and dynamic team based in Malta, working on advertising and websites. In the accounts we manage, we check the connection between the actual action and the recorded event. For an order, we look at whether Purchase appears, along with its value and currency.

Accurate measurement helps you understand your cost per order using correctly counted purchases. We explain this connection in our guide to Facebook advertising costs.

The goal of the setup is simple: events should accurately describe what happens on your website. The pixel and Conversions API are both part of that setup, and they need to be checked together. For the big picture, read our complete guide to online ads for small businesses.

What should you prepare before installing the pixel?

Before opening Events Manager, clarify what you want to measure and how your website is built. An online store and a service website have different actions to track. Your setup should start with those actions so you can later check whether the events reflect what actually happened.

For us, preparation means establishing a few practical details before adding code or connecting an integration.

1. List the actions that matter to your business: product views, additions to the cart, checkout starts, purchases, or enquiries. 2. Identify your website platform and check which official integration you can use for Conversions API. 3. Check whether a pixel is already installed and how it is added to the page. 4. Clarify the store currency and the value that should be sent for an order. 5. Check how the cookie banner passes marketing consent to the configuration in Google Tag Manager.

This preparation also gives you the criteria for your final test. You know which action you are taking, which event to expect, and which data should appear.

For the administration side, see the official Events Manager guide. In Meta, in the Events Manager section, you will create the source and monitor events. The interface may change, so focus on the purpose of each stage.

How do you create the pixel in Events Manager?

If you are wondering how to add the Facebook pixel to your website, the first step is to create it in Events Manager. Meta describes a process that starts by connecting a web data source. You then configure it on your website using your chosen installation method.

1. In Meta, in the Events Manager section, start connecting the source through Connect data. 2. Choose Web as the data source for your website. 3. Continue with Get guidance, Meta's recommended option for guided setup. 4. If you choose to configure it yourself, use Do it yourself and add the code manually.

These options are covered in the official pixel installation instructions. Interface labels and organisation may evolve. In Meta, in the Events Manager section, follow the Web source setup and the instructions available for your chosen method.

On the websites we configure, we implement the pixel through Google Tag Manager. Before publishing it, we check whether the website already loads it through another integration. You need to understand any existing installation before adding another one.

After creating the pixel, continue with the relevant events and consent rules. At this stage, you have prepared the source and installation method. Placing an actual test order is still necessary to confirm that the data arrives correctly.

Which events should you configure for a store or service business?

Standard events have predefined names that Meta recognises. Their spelling matters: event names are case-sensitive. Use ViewContent, AddToCart, or Purchase exactly as written in Meta's standard events documentation.

For a store, we track actions along the path to purchase. ViewContent corresponds to viewing the tracked content, AddToCart to adding an item to the cart, and InitiateCheckout to starting checkout. Purchase should correspond to a purchase. For service businesses, Lead can represent an enquiry submitted through a form.

For Purchase, the value parameter is required and must be a numeric amount. Meta's official example is: `fbq('track', 'Purchase', {currency: "USD", value: 30.00});`. You can find it in the conversion tracking documentation.

USD and 30.00 are the values used in the example. In your store's configuration, check the currency and value of the order you are testing. Copying the example without adapting it does not confirm that you are measuring purchases correctly.

For us, event selection starts with the visitor's actual action. A product view should remain a product view, and an enquiry should correspond to its submission. For every configured event, establish which action triggers it and test that action on the website. This gives you a clear basis for testing the whole implementation.

How do you connect the pixel in Google Tag Manager to consent?

On the websites we configure in the EU, we install the pixel through Google Tag Manager and activate it only after marketing consent is given through the cookie banner. This is the rule we follow in our implementations and check during testing.

You need to check the banner alongside the way the pixel activates. A banner displayed on the page does not, by itself, tell you whether the installation respects the visitor's choice. You need to observe how the configuration behaves before and after consent.

1. Identify the marketing choice in the banner and its connection to Google Tag Manager. 2. Configure pixel activation to depend on marketing consent. 3. Check on the website that the pixel does not activate before that consent. 4. After consent, check the events associated with the actions you are testing.

We explain the context in our guide to tracking, GDPR, and Consent Mode v2. Use it alongside a practical check of your own implementation.

For us, consent testing is part of checking the pixel. If you see an event in Events Manager, you still need to check the conditions under which it was sent. For the configuration described here, the question is simple: had the visitor given marketing consent before the pixel activated? The website's behaviour should confirm the answer.

How do you add Conversions API without duplicating events?

Meta recommends using Conversions API alongside the pixel, with the same events sent through both. This redundant setup can capture events the pixel misses because of network or loading issues. The recommendation appears in the official Conversions API guide.

Your options include partner integrations for store platforms or direct integration. Meta describes partner integrations as options that can be configured in a few clicks, with no additional integration cost. See Meta's information on setup options.

For stores on platforms such as WooCommerce or Shopify, we use the platform's official integration for Conversions API. The implementation choice should reflect the specific platform and the existing pixel configuration.

When the same action arrives through both sources, Meta needs to recognise that it is the same event. For deduplication, both copies must have the same event_name and the same event_id.

1. Configure the same relevant events through the pixel and Conversions API. 2. Check that event_name matches across copies of the same action. 3. Check that event_id matches across copies of the same action. 4. Confirm with a test order that Purchase is counted only once.

Two transmissions can describe the same purchase. Deduplication allows them to be treated as a single event, without turning one order into two reported purchases.

How do you check that the installation works correctly?

Our checks include placing a test order and comparing the data sent with the order details. We check that Purchase appears once, with the correct value and currency. If you use the pixel and Conversions API together, the checks also cover deduplication.

1. Check the consent rule before starting the purchase journey. 2. Give marketing consent and complete the actions for which you have configured events. 3. Place a test order and note its value and currency. 4. In Meta, in the Events Manager section, check the Purchase event associated with the test. 5. Compare the value and currency sent with those of the order. 6. Confirm that the same purchase is counted only once. 7. Monitor event match quality and warnings in Events Manager.

For a service website, apply the same logic to a test enquiry. The action taken on the website should correspond to the Lead event you are tracking.

In the accounts we manage, we use warnings and event match quality as checks on the configuration. We review them alongside the result of the test performed on the website.

You can return to the Events Manager guide for context on the tool. Testing is complete when you have checked which action you took, which data arrived, and whether the event was counted correctly.

Which mistakes should you check before using the data?

When the data does not match your test, start with the event and the method used to send it. Our checks focus on a few specific problems: duplicated Purchase events, missing values, incorrect currencies, a pixel activating without consent, and two pixels on the same page.

1. If Purchase is counted twice, check the sending sources and whether event_name and event_id match between the pixel and Conversions API. 2. If the value is missing, check the value parameter. For Purchase, it is required and must be a numeric amount. 3. If the currency is wrong, compare currency with the currency of the test order. Check whether USD was left in place from the code example. 4. If the pixel activates before consent, check the connection between the cookie banner and the Google Tag Manager configuration. 5. If you find two pixels on the same page, identify each installation and check which events each one sends.

Also check the spelling of event names. Uppercase and lowercase letters matter, and the names must be preserved exactly.

After making a correction, repeat the test action for the issue you identified. For purchases, confirm again that the purchase is counted once, with the correct value and currency. Then monitor warnings and event match quality in Events Manager. This lets you connect each change to a result verified on the website.

In short

A correct Meta pixel installation means relevant events, verified marketing consent, and accurate order data. Add Conversions API with deduplication, then confirm with a test order that Purchase is counted once, with the correct value and currency.
