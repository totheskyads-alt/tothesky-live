# How to connect Claude to Google Ads (MCP, 2026)

To The Sky · 25 November 2026

You can connect Claude to Google Ads through an MCP server, using Google's official connector for reporting and supported asset operations or a connector with write access for campaign changes. At To The Sky, a young, dynamic team in Malta, we use an open-source connector hosted on our own server, with safeguards and approval before changes are applied.

Connector comparison

What Claude can do once connected to Google Ads

Once connected, Claude can use the tools provided by the Google Ads MCP server to answer questions about your accounts. At To The Sky, we start with a specific performance question, then request the relevant account data. Capabilities depend on the connector we choose and the access granted to the Google account used to sign in.

Here are six prompts we use:

"Compare this month with last month, broken down by campaign."

"List search terms that spent money without generating conversions."

"Show Performance Max asset groups with low conversion value."

"Find products that have clicks but no sales."

"Prepare a negative keywords proposal for review."

"Check whether conversion actions are correctly set as primary."

These prompts give your team a useful starting point for analysis and review. A proposal remains separate from the decision to apply a change in Google Ads.

Serverul oficial Google supports reporting and diagnostics, as well as asset creation, video uploads, and label management. However, it does not create or edit campaigns. For campaign work, we use another connector with write access and safeguards. First, choose what you want to achieve, then select a connector that can do it.

Which connector to choose: official or the one we use

Conectorul oficial Google Ads MCP is open-source, written in Python, and released under the Apache-2.0 license. It works with MCP clients such as Claude and supports stdio or Streamable HTTP. Its advantage is that it provides defined tools for reporting, diagnostics, and certain management operations within an official Google project.

The available tools are list_accessible_customers, search for GAQL reporting, get_resource_metadata, create_asset, upload_video_asset, manage_labels, and manage_label_associations. The key limitation for agencies is that it does not create or edit campaigns. Choose it when its available features cover your tasks and you want to use the official option.

For campaign work at To The Sky, we use FGRibreau/mcp-google-ads. It is open-source, written in Rust, and released under the MIT license. We host it on our own server, and Claude accesses it through SSH. Its advantage is write access, along with read-only mode, a required dry run, and a daily budget cap.

The trade-off is that this option requires you to host the connector and manage server access. We recommend choosing based on the tasks you need: reporting and supported asset operations, or campaign changes that go through review and approval.

What you need before you start

Start with a Google Cloud project that has Google Ads API enabled. For the official connector, enabling the API provides Test access, which only works with test accounts. For live accounts, the project needs Explorer, Basic, or Standard access. The Cloud project that owns the OAuth client determines the access level.

Have the project ID, the JSON file containing the OAuth client details, and the path to the credentials JSON file used by the MCP server ready. The Google user you sign in with also needs Google Ads access. If you work through a manager account, MCC, prepare the login customer ID in the required format: 10 digits, without hyphens.

Google retired developer tokens on 9 September 2026. Access is now tied to the Google Cloud project, so current setup instructions need to reflect this model. Check the requirements in documentația oficială MCP.

At To The Sky, we recommend creating the project from the Google account that owns the Google Ads accounts or has a long history with them. In our experience, requests submitted from a new Google account were rejected, while the same request submitted from our established account was approved. This is an observation from our experience, not a guarantee of approval.

Set up the connection step by step

For the official Google Ads MCP option, we follow the steps in this order. We handle project approval, authentication, and the client connection separately so that we can check each prerequisite before requesting data from a live account.

1. Create the Google Cloud project from the appropriate Google account and enable Google Ads API. If the project only has Test access, use it with test accounts until you obtain the access level required for live accounts.

2. Check that the project that owns the OAuth client has Explorer, Basic, or Standard access for use with live accounts. Do not assume that enabling the API also means the project is approved for production.

3. Publish the OAuth consent screen to Production. In Testing, Google expires authentication after 7 days, and the connector stops working. Include this check when preparing a connection you plan to keep using.

4. Prepare the OAuth client JSON file and replace PATH_TO_CLIENT_SECRET_JSON with its actual path. Sign in using the command below, keeping the specified scopes.

gcloud auth application-default login --scopes=https://www.googleapis.com/auth/adwords,https://www.googleapis.com/auth/cloud-platform --client-id-file=PATH_TO_CLIENT_SECRET_JSON

5. Note the project ID and the credentials file path for the MCP configuration in the next section. Keep these values tied to the same project and access context, then move on to connecting the server in Claude.

Connect the MCP server to Claude

For the official connector, configure an entry in mcpServers using the documented values. Set command to "pipx" and args to ["run","--spec","google-ads-mcp==0.0.6","google-ads-mcp"]. These are configuration fields, not separate commands to run one after another. Keep the package specification value exactly as shown in this configuration.

In env, set GOOGLE_CLOUD_PROJECT to PROJECT_ID and GOOGLE_APPLICATION_CREDENTIALS to PATH_TO_CREDENTIALS_JSON. Replace the placeholder values with your project ID and credentials file path. To work through a manager account, you can add GOOGLE_ADS_LOGIN_CUSTOMER_ID, using the 10 digits without hyphens.

These values are documented for serverul oficial Google Ads MCP. The server supports stdio and Streamable HTTP and works with MCP clients such as Claude. Make sure the project in the configuration matches the access context you prepared.

Our campaign setup uses a different option: we host FGRibreau/mcp-google-ads on our own server and access it from Claude through SSH. For this option, follow instrucțiunile proiectului for installation and configuration. The pipx settings above belong to Google's official server. Once connected, we verify access with a reporting request before preparing any campaign changes.

Test the connection with your first prompt

The first check should confirm that Claude can read the correct account. At To The Sky, we start with a reporting request that explicitly specifies the customer ID and makes no changes. This gives you clear context for both the result and any access errors.

Use this first prompt, replacing CUSTOMER_ID with the ID of the account you want to check:

"For Google Ads account CUSTOMER_ID, compare this month with last month, broken down by campaign. Show spend, conversions, and conversion value, and specify the periods being compared. Only read the data; do not change anything."

Before interpreting performance, check that the response covers the requested account and periods. You can then ask for search terms that spent money without conversions or products with clicks but no sales. Build out the analysis from a connection you have already verified.

If listing accounts returns a permission error, test the account directly using its customer ID. In our experience, an error when listing accounts does not always mean you lack access to that account.

Test Keyword Planner ideas and forecasts separately. In our setup, these require Basic access. At a lower level, reporting and campaign changes may work while keyword ideas return a permission error.

Safety and permissions: who approves changes

Treat data access and approval of changes as separate decisions. Keep read-only mode enabled for analysis. The connector we use for campaigns includes safeguards for read-only mode, a required dry run, and a daily budget cap. We keep these active in our workflow and request approval before applying changes.

A dry run means a proposal you review and confirm before it is applied. For example, you can ask Claude to prepare negative keywords for review. Assess the proposal in the context of the account before authorizing the change. A request for analysis or for a proposal must not be treated as approval to publish.

Decide who approves changes before starting any work that involves write access: the person responsible for the Google Ads account or the client representative designated to approve changes. We recommend that this person check what will change and any budget implications. Claude prepares the proposal, and the designated person makes the decision.

Set the daily cap based on the account's approved budget. The cap complements human review. Also remember that Google's official server includes write operations for assets and labels, even though it does not edit campaigns. Choose tools and permissions based on the task you have approved.

Common traps and how to avoid them

Check production approval before troubleshooting the Claude connection. For live accounts, a project with only Test access triggers the AuthorizationError.CLOUD_PROJECT_NOT_APPROVED_FOR_PRODUCTION error. Confirm the access level of the Cloud project that owns the OAuth client, because that project determines access. Documentația Google explains this requirement.

Publish the OAuth consent screen to Production for a setup you plan to keep using. In Testing, authentication expires after 7 days. Check this status before relying on the connector for the agency's day-to-day work.

Choose the login customer ID based on how you were granted access. If a client shared their account directly with your Google user and the account is not under your manager account, set the login customer ID to the client's account. In our setup, using a different context in this situation causes a permission error.

Check each feature separately. An error when listing accounts calls for a direct test using the customer ID. An error with Keyword Planner ideas calls for checking the Basic access level. Neither automatically means that all connector features are unavailable.

Finally, check that you have chosen the right connector for the task. The official server does not create or edit campaigns. For these operations, use an option with write access and keep proposal review in place before applying changes.

In short

To connect Claude to Google Ads, choose the connector around your required tasks, prepare Google Cloud project access, and verify a specific account with a reporting request. For campaign changes, use a connector with write access, a required dry run, a budget cap, and a designated person who approves each proposal.
