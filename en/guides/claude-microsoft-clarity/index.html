What you need

What you get when you connect Claude to Clarity

At my agency, I use this connection to stop watching recordings one by one without a clear question. Claude helps me identify problems in Clarity data and choose the sessions worth watching. I can start with a page, a behaviour or a problem, then ask for the recordings behind the answer.

Once connected, I can ask why people leave a page and where they stop scrolling. I can check where they rage-click, where they click on things that do not work, and how many leave right after an ad click. Clarity calls those quick returns “quick backs”. These give me specific behaviours to investigate.

I also use the connection to check JavaScript errors and the browsers affected. For a shop, I can ask for sessions that almost ended in a sale. That gives me a reason to open a recording instead of working through sessions without knowing what I am looking for.

The connection uses the Clarity MCP server, Microsoft's official, free connector. It reads Clarity data. It cannot change your website or your Clarity settings. I use it to help investigate what happens on a page.

What I prepare before setup

I need Microsoft Clarity installed on the website, Claude Code and Node.js installed. For Claude Code, I can use the terminal or the Code tab of the Claude desktop app. The setup in this guide takes about 10 minutes and has two parts: create the token in Clarity, then add the connector to Claude.

Before starting, I choose the site I want to review. A Clarity token belongs to one project. If you manage several sites, create one token for each and keep them separate. I also use a separate connector with a clear name for each site, so the project and connector do not get mixed up.

I prepare a private settings file on my computer for the token. I never paste it into a chat, a document or a shared folder. Clarity displays it only once, so I copy it as soon as it is generated and keep it in that private file.

I complete both setup steps in the same sitting. Generating a token alone does not connect Claude to Clarity.

Step 1: create an API token in Microsoft Clarity

I start in Clarity, inside the project for the site I want to check. The token I create here is the one I will use in the Claude command.

1. Open clarity.microsoft.com and choose your project.

2. Go to Settings → Data export.

3. Click Generate new API token and give it a name, for example “Claude”.

4. Copy the token immediately. Clarity shows it only once.

5. Keep the token in a private settings file on your computer.

Do not treat tokens from different sites as interchangeable. One token means one project. If you work with several projects, create a token for each site and keep them apart.

If you closed the token display before copying it, or you lost the token, generate a new one. Then continue to the next step. At this point you have the token, but you still need to add the connector to Claude.

Step 2: add the Clarity MCP server to Claude Code

Once I have the token, I move to Claude Code. This is the step that actually adds the connector. If I stop after generating the token in Clarity, the connection is not set up.

1. Open Claude Code in the terminal or in the Code tab of the Claude desktop app.

2. In the command below, replace [your token] with the token for your selected project.

3. Run the command to add the connector.

claude mcp add clarity -- npx -y @microsoft/clarity-mcp-server --clarity_api_token=[your token]

4. Restart Claude before testing the connection.

For several sites, I add one connector per site and give each a clear name, such as clarity-shopname. I keep the same rule on both sides: one token per site and one connector per site.

I do not skip the restart. Claude loads a new connector after a restart or in a new chat. If it does not appear in the current conversation, I check that before treating the setup as a failure.

Test the connection with a rage-click question

After restarting, I use a specific question about recent data. This is the test prompt from my setup:

“Show me the rage clicks on mobile for the last 3 days.”

The question names the behaviour, device and period. It also stays within the connector's window of the last 1 to 3 days. I do not start the test by asking about last month, because older periods belong in the Clarity dashboard.

If Claude says it is not connected, I check whether I completed step 2. Creating the token in Clarity does not automatically add it to Claude. If the new connector is missing, I restart Claude or open a new chat.

Once I get a finding, I ask for the sessions behind it. I use the answer as a starting point for watching what people did on the page. A number alone is not enough for me to decide what to change.

The questions and prompts I use

At my agency, I start with the question I need to answer. Sometimes I am reviewing a pricing page. Other times I am looking at paid traffic, checkout or mobile behaviour. These are the prompts I use to move from a question to relevant data and sessions.

Why people leave:

“Why do people leave my pricing page? Show scroll depth, quick backs and clicks that go nowhere.”

Frustration:

“Which pages have the most rage clicks and dead clicks? What are people clicking on?”

Paid traffic:

“Compare quick backs from paid social and Google Ads with organic traffic.”

Almost bought:

“Find sessions where people added to cart but didn't buy. Pick 5 I should watch, with links.”

Errors:

“Which JavaScript errors happen on checkout, and on which browsers?”

Landing page:

“How far do people scroll on my main landing page on mobile? Where do most stop?”

Speed:

“How are the page speed scores on mobile vs desktop?”

Summary:

“Give me the 3 biggest problems on the site this week, each with one session to watch.”

For that last prompt, I keep the available reporting window in mind. Saying “this week” does not give the connector access beyond the last 1 to 3 days. For an older period, I open the Clarity dashboard.

The traps I hit and how I fix them

The token disappeared. Clarity shows it only once. If I lost it, I generate a new one and keep it in a private settings file. I do not rely on being able to view the same token again later.

Claude says it is not connected. I check whether I only created the token without adding it to Claude. I fix that by completing step 2 with the command on this page. This is why I prefer to create the token and add the connector in the same sitting.

The new connector does not appear. Claude loads it after a restart or in a new chat. I restart Claude or begin a new chat before testing again.

I ask about last month. The connector sees only the last few days. For older periods, I use the Clarity dashboard.

I mix up sites. I keep one token and one connector per site, with clear names. When I manage several projects, that separation helps me keep track of the site I am reviewing.

I see far fewer sessions than expected. In the EU, Clarity needs consent from the cookie banner. Without it, you will see far fewer sessions. I keep that condition in mind when interpreting the available data.

How I read the answers before changing a page

A quick exit is not automatically a problem. Someone may find the phone number and call. If I look only at the exit without watching the session, I can misread what happened. That is why I watch the recordings before changing the page.

Dead clicks show expectations. If something looks like a button, people may click it. Often the fix is to make it a button. I use that signal to understand what a visitor expected to happen, then look at the sessions.

I ask for the sessions behind each finding. Three recordings I have watched are more useful to me than a hundred numbers without context. I want to see the behaviour that led to Claude's answer.

Claude does not know my customers. It can help me find behaviours and choose what to watch, but I decide what that behaviour means and what to change on the page. I keep that responsibility with me when reviewing pages at my agency.

What the connector can read and what it cannot do

The Clarity MCP server reads dashboard metrics: dead clicks, rage clicks, quick backs, scroll depth, JavaScript errors and page speed. It can also read session recordings with filters and the Clarity documentation. Those are the sources I rely on when asking the questions above.

The connector is read-only. It cannot change the website or the Clarity settings. If a finding makes me want to change something on a page, this connection does not make that change for me.

The time limit matters just as much: the connector sees the last 1 to 3 days. For older periods, I open the Clarity dashboard. Asking about last month does not change that limit.

Finally, behaviour data still needs interpretation. A quick exit may mean the visitor found what they needed. A dead click may show that an element looks interactive. I use Claude to find what deserves a closer look, watch the sessions, and decide what it means for that page.

In short

I connect Claude to Microsoft Clarity in two steps: create a project token, then add the Clarity MCP server to Claude Code and restart Claude. I test with the mobile rage-click question, then ask for the sessions behind each finding. For data older than the last 1 to 3 days, I use the Clarity dashboard.
