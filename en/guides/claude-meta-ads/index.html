How to connect Claude to Meta Ads: official MCP, 2026

To The Sky · 25 November 2026

You can connect Claude to Meta Ads by adding Meta's official Ads MCP server as a custom connector and signing in through Meta. At To The Sky, an ads and web agency with a young, dynamic team in Malta, we use this connection to analyse client accounts and prepare paused advertising drafts for human review.

Connector comparison

What Claude can do once connected to Meta Ads

At To The Sky, we use Meta's official Ads MCP server for our clients' advertising accounts. In the setup we use, Claude can read accounts, campaigns, ad sets, ads, creatives and insights. It can also create campaigns, ad sets, ads and creatives. That gives us a practical path from reviewing performance to preparing advertising work within the same conversation.

Here are example requests we use or adapt to the account:

"Which ad sets have cost per result above target this week, and why?"

"Compare creatives by click-through rate and cost per result."

"Check frequency and signs of creative fatigue."

"Draft a new ad set with the best audience, paused, for review."

"List ads with rejected or limited delivery."

"Summarise spend and results by campaign for the client report."

"List the images in this account with their URLs so we can choose by offer and format."

Give each request an account, a reporting period and any relevant target. When asking for an explanation, request the supporting evidence so the interpretation can be reviewed. In our use, new campaigns, ad sets and ads are created paused, as drafts. We treat those drafts as review material, with a person deciding what gets activated.

Which connector to choose and what we use

The connector we use is Meta's official Ads MCP server. To choose your setup, compare the ways of connecting to that server. The official Meta documentation describes the server and its supported authentication methods.

For Claude desktop or web, you can add the server as a custom connector and sign in through Meta. The practical advantage is that you do not need your own Meta app. You still need to approve permissions, and the available tools depend on the access granted. This is the route we describe for marketers who want to work directly in the Claude app.

If you choose Claude Code with your own Meta developer app, you add the specified use case, configure the redirect URL and connect using the command below. This route suits teams choosing to use their own application. Its tradeoff is the additional app and redirect configuration.

Meta also supports a user access token or an Employee-role system user token. An Admin-role system user token cannot access the server. Choose the authentication route with whoever manages Meta access. Our connection uses the official server; the different authentication methods are ways into that same server.

What you need before you start

Start by choosing where you will use the connection: Claude desktop, Claude web or the Claude Code route described here. For OAuth through Facebook Login for Business, you sign in with a Facebook account or Meta Managed Account and approve permissions. Identify the intended advertising account beforehand so you can check that Claude reads the correct account.

The minimum permissions are ads_mcp_management plus either ads_read or ads_management. For a reporting-focused start, our recommended choice is ads_read alongside ads_mcp_management. For work involving changes, review the need for ads_management. Additional permissions that unlock more tools include ads_management, catalog_management, business_management, pages_show_list and instagram_basic.

You do not need your own Meta app, as explained in Meta's help article. If you choose the route with your own developer app, prepare its app ID and redirect URL configuration. If using a system user token, check that it has the Employee role.

Also prepare the working context: reporting period, target cost per result, offer and the person responsible for approving activation. For image-based creatives, the images must already exist in the advertising account. These details help us turn a working connection into a useful workflow.

Setup step by step

1. Choose your connection route. For Claude desktop or web, prepare to add a custom connector. If choosing Claude Code with your own Meta developer app, also complete the app configuration steps below.

2. Use Meta's official Ads MCP server. The server address is https://mcp.facebook.com/ads. Keep this address as the destination for the connection.

3. Decide which permissions fit the work. The minimum requirement is ads_mcp_management plus ads_read or ads_management. For the initial check, we recommend starting with reading data and considering the need for changes separately.

4. If using your own Meta developer app, add the use case with the exact name "Create & manage ads with ads MCP server" and set the redirect URL. This step applies to the route using your own application.

5. For that route in Claude Code, replace <META_APP_ID> with your application's ID in the following command:

claude mcp add --transport http --client-id <META_APP_ID> meta-ads https://mcp.facebook.com/ads

6. Continue with authentication and account verification. Before requesting advertising creation, establish that proposed drafts should remain paused until a person approves them. At To The Sky, we separate access checks from advertising reviews so each stage has a clear outcome.

Connect the server to Claude

In the Claude desktop or web app, add a custom connector with the address https://mcp.facebook.com/ads. When the Meta window opens, sign in and review the requested permissions. With OAuth, authentication uses Facebook Login for Business with your Facebook account or Meta Managed Account.

Approve the permissions appropriate to the intended work. In the workflow we recommend, the first task is reading account data. If you also need creation capabilities, review the required access separately. A clear working objective helps you decide which permissions to grant.

If your chosen authentication method uses a user access token, Meta accepts the token in the Authorization: Bearer header. Meta also accepts an Employee-role system user token. The Admin role for a system user token is not supported for access to this server. These are authentication alternatives supported by the server; the custom connector steps described here use the Meta sign-in window.

After connecting, verify access with a reading request. We recommend first confirming which account Claude can access, then asking for a campaign summary. This lets you check that the connection serves the intended client and advertising account before moving on to draft preparation.

Test the connection with your first prompt

For the first test, use a request that checks access and produces a summary you can evaluate. We recommend starting with reading data, then moving to more detailed questions once you have confirmed the account and reporting period.

"List the advertising accounts you can read. Ask me to confirm the account, then summarise spend and results by campaign for this week. Make no changes. State the account and reporting period used, and flag any missing information."

After confirming the account, check whether the summary answers the actual business question. Ask for an ad set breakdown if you need to investigate cost per result, then compare creatives by click-through rate and cost per result. For recommendations, supply your target and request the evidence supporting the interpretation.

Test draft preparation separately when you are ready to use creation capabilities. Explicitly request that the new ad set remain paused, and review the result before activation. In our use, new campaigns, ad sets and ads are created paused. For image-based creatives, first request the existing images and their URLs. Choose the image that fits the offer and format, then ask Claude to use it by its image hash.

Safety, permissions, budgets and approval

At To The Sky, we keep a clear separation between analysis, draft preparation and activation. For read-only work, start with ads_mcp_management and ads_read. If the task requires changes, assess ads_management and any other relevant permissions. Match access to the work you intend to delegate.

In our use, new campaigns, ad sets and ads are created paused, as drafts, so they do not spend until a person activates them. Keep that requirement explicit in your prompt and verify the resulting status. A draft prepared by Claude should pass through the responsible person's review before activation.

Decide who approves the audience, creative and budget before requesting creation. Our recommendation is to designate a person responsible for the account to approve activation. If client approval is required, include it in the process before that decision.

For a hard monthly spending cap, we rely on Meta's own account spending limit and automated rules, which run on Meta's side. Claude works when you ask it; it does not monitor the account continuously. Configure budget protections in Meta and use Claude for requested checks, analysis and preparation. Conversation instructions should be supported by the account's actual controls.

Common traps and how to avoid them

Prepare images before requesting a new creative. In our use, creatives need images that already exist in the advertising account, and external image links are rejected. Upload images to the account once, then ask Claude to use them by image hash. You can request the image list with URLs to select by offer and format.

Check the token type if choosing system user authentication. Meta supports an Employee-role token, while Admin-role tokens cannot access this server. Also confirm the minimum permission combination: ads_mcp_management plus ads_read or ads_management. Additional permissions unlock more tools, so relate the required access to the specific task.

Keep the distinction between recommendation and approval clear. When asking for the best audience or an explanation of weak results, provide the objective and request supporting data. Verify the paused status of drafts before the responsible person decides on activation.

Finally, configure budget protection where it runs: in Meta. We use account spending limit and automated rules for the monthly cap. Plan Claude checks as actions you request. That gives analysis, human approval and spending controls a clear role in the workflow.

In short

Connect Claude through Meta's official Ads MCP server, verify access with a reading request, and prepare paused drafts for approval. At To The Sky, we keep activation with a person and use Meta's own controls to protect the budget.
