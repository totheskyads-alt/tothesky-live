Cum conectezi Claude la Microsoft Clarity

To The Sky · Actualizat 24 noiembrie 2026

Ca să conectezi Claude la Microsoft Clarity, creezi un API token pentru proiectul tău, apoi adaugi connectorul oficial Microsoft în Claude Code cu comanda de mai jos. Eu folosesc această configurare la agenția mea, To The Sky, ca să verific datele din Clarity și să aleg înregistrările care merită urmărite. Toți pașii sunt pe această pagină, iar PDF-ul rămâne disponibil ca descărcare opțională.

Ce îți trebuie

Ce obții când conectezi Claude la Clarity

La agenția mea folosesc această conexiune ca să nu urmăresc înregistrările una câte una, fără o întrebare clară. Claude mă ajută să identific probleme în datele Clarity și să aleg sesiunile pe care merită să le văd. Pot porni de la o pagină, un comportament sau o problemă, apoi cer înregistrările din spatele răspunsului.

După conectare, pot întreba de ce pleacă oamenii de pe o pagină și unde se opresc din scroll. Pot verifica unde apar rage clicks, unde oamenii apasă pe elemente care nu reacționează și câți pleacă imediat după un click pe reclamă. În Clarity, aceste plecări rapide apar ca „quick backs”.

Mai folosesc conexiunea pentru a verifica erorile JavaScript și browserele pe care apar. Pentru un magazin online, pot cere sesiuni care aproape s-au încheiat cu o vânzare. Așa aleg ce urmăresc, în loc să deschid înregistrări la întâmplare.

Conexiunea folosește Clarity MCP server, connectorul oficial și gratuit de la Microsoft. Acesta citește datele din Clarity. Nu poate modifica site-ul sau setările Clarity. Pentru mine, rolul lui este să mă ajute să investighez ce se întâmplă pe pagină.

Ce pregătesc înainte de configurare

Am nevoie de Microsoft Clarity instalat pe site, Claude Code și Node.js instalat. Pentru Claude Code pot folosi terminalul sau tabul Code din aplicația Claude pentru desktop. Configurarea din ghid durează aproximativ 10 minute și are doi pași: creez tokenul în Clarity, apoi adaug connectorul în Claude.

Înainte să încep, aleg site-ul pe care vreau să îl analizez. Un token Clarity corespunde unui singur proiect. Dacă gestionezi mai multe site-uri, ai nevoie de un token pentru fiecare și trebuie să le păstrezi separat. Eu folosesc și câte un connector cu un nume clar pentru fiecare site.

Îmi pregătesc un fișier privat de setări pe computer pentru token. Nu îl lipesc într-un chat, într-un document sau într-un folder partajat. Clarity îl afișează o singură dată, așa că îl copiez imediat după generare și îl păstrez în acel fișier privat.

Fac ambii pași în aceeași sesiune. Simplul fapt că am generat tokenul nu înseamnă că am conectat Claude la Clarity.

Pasul 1: creează un API token în Microsoft Clarity

Încep în Clarity, în proiectul site-ului pe care vreau să îl verific. Tokenul pe care îl creez aici este cel pe care îl voi folosi în comanda pentru Claude.

1. Deschide clarity.microsoft.com și alege proiectul tău.

2. Mergi la Settings → Data export.

3. Apasă Generate new API token și dă-i un nume, de exemplu „Claude”.

4. Copiază tokenul imediat. Clarity îl afișează o singură dată.

5. Păstrează tokenul într-un fișier privat de setări pe computer.

Nu trata tokenurile de la mai multe site-uri ca și cum ar fi interschimbabile. Un token înseamnă un proiect. Dacă lucrezi cu mai multe proiecte, creează câte unul pentru fiecare site și ține-le separat.

Dacă ai închis afișarea tokenului înainte să îl copiezi sau l-ai pierdut, generează unul nou. Apoi continuă cu pasul următor. În acest moment ai tokenul, dar încă trebuie să adaugi connectorul în Claude.

Pasul 2: adaugă Clarity MCP server în Claude Code

După ce am tokenul, trec la Claude Code. Acesta este pasul care adaugă efectiv connectorul. Dacă mă opresc după generarea tokenului în Clarity, conexiunea nu este configurată.

1. Deschide Claude Code în terminal sau în tabul Code din aplicația Claude pentru desktop.

2. În comanda de mai jos, înlocuiește [your token] cu tokenul proiectului ales.

3. Rulează comanda pentru a adăuga connectorul.

claude mcp add clarity -- npx -y @microsoft/clarity-mcp-server --clarity_api_token=[your token]

4. Repornește Claude înainte să testezi conexiunea.

Pentru mai multe site-uri, adaug câte un connector pentru fiecare și îi dau un nume clar, cum ar fi clarity-shopname. Păstrez aceeași regulă pe ambele părți: un token pentru fiecare site și un connector pentru fiecare site.

Nu sar peste repornire. Claude încarcă noul connector după o repornire sau într-un chat nou. Dacă nu îl văd imediat în conversația curentă, verific acest lucru înainte să consider că am greșit configurarea.

Testează conexiunea cu o întrebare despre rage clicks

După repornire, folosesc o întrebare concretă despre date recente. Acesta este promptul de test din configurarea mea:

„Arată-mi rage clicks pe mobil din ultimele 3 zile.”

Întrebarea precizează comportamentul, dispozitivul și perioada. Se încadrează și în limita connectorului, care vede ultimele 1 până la 3 zile. Nu încep testul cu o întrebare despre luna trecută, pentru că datele mai vechi trebuie verificate în dashboardul Clarity.

Dacă Claude spune că nu este conectat, verific dacă am făcut și pasul 2. Crearea tokenului în Clarity nu îl adaugă automat în Claude. Dacă noul connector nu apare, repornesc Claude sau deschid un chat nou.

După ce primesc un rezultat, cer sesiunile din spatele constatării. Folosesc răspunsul ca punct de plecare pentru a vedea ce au făcut oamenii pe pagină. Nu decid ce schimb doar dintr-un număr.

Întrebările și prompturile pe care le folosesc

La agenția mea pornesc de la întrebarea la care vreau să răspund. Uneori verific o pagină de prețuri. Alteori mă interesează traficul din reclame, checkoutul sau comportamentul pe mobil. Acestea sunt prompturile pe care le folosesc pentru a trece de la o întrebare la date și sesiuni relevante.

De ce pleacă oamenii:

„De ce pleacă oamenii de pe pagina mea de prețuri? Arată-mi scroll depth, quick backs și clickurile pe elemente care nu reacționează.”

Frustrare:

„Ce pagini au cele mai multe rage clicks și dead clicks? Pe ce dau click oamenii?”

Trafic plătit:

„Compară quick backs din paid social și Google Ads cu cele din traficul organic.”

Aproape de cumpărare:

„Găsește sesiuni în care oamenii au adăugat produse în coș, dar nu au cumpărat. Alege 5 pe care să le urmăresc și dă-mi linkurile.”

Erori:

„Ce erori JavaScript apar la checkout și pe ce browsere?”

Landing page:

„Cât de mult fac scroll oamenii pe landing page-ul meu principal, pe mobil? Unde se opresc cei mai mulți?”

Viteză:

„Cum sunt scorurile de viteză ale paginilor pe mobil față de desktop?”

Rezumat:

„Dă-mi cele mai mari 3 probleme ale site-ului din această săptămână, fiecare cu o sesiune de urmărit.”

La ultimul prompt țin cont de limita perioadei disponibile. Formularea „din această săptămână” nu îi oferă connectorului acces la mai mult decât ultimele 1 până la 3 zile. Pentru o perioadă mai veche, deschid dashboardul Clarity.

Capcanele pe care le-am întâlnit și cum le rezolv

Tokenul a dispărut. Clarity îl afișează o singură dată. Dacă l-am pierdut, generez unul nou și îl păstrez într-un fișier privat de setări. Nu mă bazez pe faptul că îl voi putea vedea din nou mai târziu.

Claude spune că nu este conectat. Verific dacă am creat doar tokenul, fără să îl adaug în Claude. Rezolv prin pasul 2, folosind comanda de pe această pagină. De aceea prefer să creez tokenul și să adaug connectorul în aceeași sesiune.

Noul connector nu apare. Claude îl încarcă după repornire sau într-un chat nou. Reporneasc aplicația sau încep un chat nou înainte să testez din nou.

Cer date despre luna trecută. Connectorul vede doar ultimele zile. Pentru perioade mai vechi, folosesc dashboardul Clarity.

Încurc site-urile. Păstrez câte un token și câte un connector pentru fiecare site, cu nume clare. Când gestionez mai multe proiecte, această separare mă ajută să știu ce site analizez.

Văd mult mai puține sesiuni decât mă așteptam. În UE, Clarity are nevoie de consimțământ prin bannerul de cookies. Fără acesta, vor apărea mult mai puține sesiuni. Țin cont de această condiție când interpretez datele disponibile.

Cum citesc răspunsurile înainte să schimb pagina

O ieșire rapidă nu înseamnă automat o problemă. Cineva poate găsi numărul de telefon și poate suna. Dacă mă uit doar la plecare, fără să urmăresc sesiunea, risc să interpretez greșit ce s-a întâmplat. De aceea verific înregistrările înainte să schimb pagina.

Dead clicks arată ce se așteaptă oamenii să poată face. Dacă un element arată ca un buton, oamenii pot apăsa pe el. Deseori, rezolvarea este să îl transformi într-un buton. Folosesc acest semnal ca să înțeleg așteptarea vizitatorului, apoi mă uit la sesiuni.

Cer sesiunile din spatele fiecărei constatări. Trei înregistrări pe care le-am urmărit îmi sunt mai utile decât o sută de numere fără context. Vreau să văd comportamentul care a dus la răspunsul lui Claude.

Claude nu îmi cunoaște clienții. Mă poate ajuta să găsesc comportamente și să aleg ce urmăresc, dar eu decid ce înseamnă acel comportament și ce schimb pe pagină. Păstrez această responsabilitate la mine când verific pagini pentru agenție sau pentru clienți.

Ce poate citi connectorul și ce nu poate face

Clarity MCP server citește metricile din dashboard: dead clicks, rage clicks, quick backs, scroll depth, erori JavaScript și viteza paginilor. Mai poate citi înregistrările sesiunilor cu filtre și documentația Clarity. Acestea sunt sursele pe care mă bazez când pun întrebările de mai sus.

Connectorul are acces doar pentru citire. Nu poate modifica site-ul și nici setările Clarity. Dacă o constatare mă face să vreau o schimbare pe pagină, conexiunea nu face acea schimbare în locul meu.

Limita de timp este la fel de importantă: connectorul vede ultimele 1 până la 3 zile. Pentru perioade mai vechi, deschid dashboardul Clarity. O întrebare despre luna trecută nu schimbă această limită.

În final, datele despre comportament au nevoie de interpretare. O plecare rapidă poate însemna că vizitatorul a găsit ce îi trebuia. Un dead click poate arăta că un element pare interactiv. Eu folosesc Claude ca să găsesc ce merită verificat, urmăresc sesiunile și decid ce înseamnă pentru pagina respectivă.

Pe scurt

Eu conectez Claude la Microsoft Clarity în doi pași: creez un token pentru proiect, apoi adaug Clarity MCP server în Claude Code și repornesc Claude. Testez cu întrebarea despre rage clicks pe mobil, apoi cer sesiunile din spatele fiecărei constatări. Pentru date mai vechi decât ultimele 1 până la 3 zile, folosesc dashboardul Clarity.
